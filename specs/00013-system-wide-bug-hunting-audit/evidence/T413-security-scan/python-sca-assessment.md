## Release conclusion

**Gate status: BLOCKED** pending 27 dependency-lock upgrades and formal approval of 42 short-lived API-disjointness exceptions. Reachability evidence does not auto-waive the clean-SCA policy.

No critical/high advisory has a proven reachable or uncertain PB product path after static source/control/sink validation. This is not a clean-SCA result: fixed leaf/framework packages still require lock upgrades, while Torch/Transformers require explicit short-lived exceptions until AMD-compatible upgrades are proven.

The sole `uncertain` disposition is CVE-2026-45409 (idna): configurable HTTP hostnames may transitively invoke `idna.encode`, but static code cannot prove whether an attacker-controlled long Unicode hostname reaches that sink. Upgrade to 3.15.

## Critical/high advisory validation

- **CVE-2025-32434 (Critical 9.3)** and **CVE-2026-24747 (High 8.8):** no PB `torch.load` call; the release stem path is a closed enum and the approved bundle ships hash-pinned ONNX weights. `htdemucs.yaml` is enumerated but absent from the bundle, so it fails before checkpoint load. Time-bounded exception only; reassess if any PyTorch checkpoint is shipped.
- **CVE-2026-4372 (High 7.8):** the vulnerable `AutoModelForCausalLM.from_pretrained` sink exists in `moondream_pytorch.py`, but has no production caller and forces offline/local-only mode. The local Hugging Face cache is not hash-verified; remove or harden this dormant loader before enabling it.

## Exception policy

Every `time-bounded-exception` expires within 30 days or at the next compatible lock refresh, whichever comes first. Any addition of a PyTorch checkpoint, remote Hugging Face model, generic Pillow document input, Starlette form/static/class endpoint, or urllib3 client invalidates the matching exception and requires reassessment.
